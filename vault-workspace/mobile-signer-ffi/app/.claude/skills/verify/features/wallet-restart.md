# Wallet restart

On iOS a software wallet that was created or imported is saved on the phone. A cold start then opens an unlock screen with the Face ID card instead of Welcome, and a match opens Home with the same key. A payment whose outcome is not known is saved with the wallet, so after a restart Send and Review still refuse to pay it again. A reinstall erases the wallet that the deleted install left, and Forget erases it on purpose. On Android (API 30 and up, with a screen lock) the wallet is saved the same way under a Keystore key, and a cold start opens the unlock screen with the system PIN or fingerprint prompt.

## Sub-features

- `wr-saved-copy` Key Created says that deleting the app loses the wallet when the store saved it.
- `wr-enable-readback` App Lock Enable on a saved wallet reads the saved copy back with the one Face ID card.
- `wr-cold-unlock` a cold start opens the unlock screen with the card, and a match opens the Wallet list, whose card opens Home with the same key.
- `wr-unconfirmed-send` a payment of unknown outcome still blocks Send and Review after a kill, a relaunch and the unlock, until a loaded history lists its txid or the user confirms the clear control (`unconfirmed_clear`, offered after two minutes by the phone clock, which only decides when to offer it). The guard is saved before the post, so a kill during the post still blocks.
- `wr-miss-cancel` a miss shows iOS's own card, and Cancel leaves the screen waiting with its button.
- `wr-reinstall-wipe` a reinstall erases the old wallet, and Welcome says so once.
- `wr-forget` Forget from the unlock screen asks for a confirm and then the owner. From the recovery screen the confirm alone erases.
- `wr-not-saved` the not-saved notice on Key Created, the Wallet list and S1, with a text for each reason.
- `wr-vault-book` the keys and vaults of a saved wallet are back after a restart, with the one Face ID card of the unlock.
- `wr-android-store` Android saves the key, a cold start asks for the PIN once and opens Home with the same key, Cancel leaves the button, a removed PIN opens the recovery screen, and Forget erases.

## How to get to it (user POV)

- Create or import a wallet, finish App Lock, then close the app and open it again.
- Sign a payment that ends with ยังไม่ทราบผลการส่ง, close the app, open it again, unlock and go to Send.
- Unlock screen → ใช้ 24 คำแทน → ลบออกจากเครื่องนี้ → the owner check → Welcome.
- Delete the app, install it again and open it.
- Android: set a screen lock, create a wallet, close the app and open it again.

## Gotchas

- `ios-start` failed once with `Simulator with the ID ... is not a known/supported destination for this project` right after the boot. The failed start removed `build/verify/ios.env` but left its simulator booted. Writing its `IOS_RUN` and `UDID` back into `ios.env` and running `ios-stop` deleted it, and the next `ios-start` passed. The cause was the iPhone's `ios.env` that was still in place. `cmd_ios_start` sources the old file before it deletes it, so `IOS_DEVICE=1` stays set in that shell, and the cleanup after a failed start takes the phone branch and never deletes the simulator. Move the iPhone's `ios.env` away before `ios-start` (a copy is not enough, the original has to be gone) and move it back after `ios-stop`.
- With Face ID not enrolled, a saved wallet's Enable tap opens iOS's passcode sheet (Enter iPhone Passcode for "mebit"), which a simulator run cannot answer. Enrol Face ID before App Lock.
- In this shell `ls` is an alias that puts a space before each name, so a path taken from its output does not open. Write the keychain database path out.
- `verify.sh doctor` reads `build/verify/ios.env`. When that file names the iPhone, `doctor` queries the phone and reports its app as not running.
- On the iPhone, `ios-stop` uninstalls the app, so the next `ios-start` is a fresh install, and its first launch erases the wallet that the old install left. The recipes therefore still start at Welcome. That follows from the reinstall rule and has not run on the phone yet.
- With the step 9 probe the history loads, so the history lists no txid of the probe, so no bind settles the payment any more (the clock no longer clears it) and only the clear control does. Send and Review do not bind, so they can be checked later.
- A `simctl io` screenshot taken a second after `simctl launch` showed the launch animation, not the unlock card. Take another before `pearl.match`.
- `xcrun simctl launch --stdout=<file>` with a relative path is refused with `The request was denied by service delegate (SBMainWorkspace)`, and SpringBoard logs `Launchd job spawn failed`. Pass absolute paths.
- The emulator's Keystore is software (security level 0), it has no StrongBox, and it runs API 36 only. The POCO X3 NFC (Android 11, MIUI V125) ran it on 3 Nov 2026 (create, Enable, cold unlock with the same fingerprint, 60 s lock, two wrong scans and Cancel all pass; `adb install -r` works there). The prompt's "ใช้ PIN" button opens the wallet with the screen PIN and no fingerprint (counters unchanged). MIUI face unlock is not offered to the app. Not run on it yet: removed screen lock, Forget, a new fingerprint enrolled after the key exists.
- A simulator enforces no Keychain access control and always has a passcode. The number of OS sheets on an iPhone, the no-passcode path, and the item's deletion when the passcode is removed cannot be checked here.
