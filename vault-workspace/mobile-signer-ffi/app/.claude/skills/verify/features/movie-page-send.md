# Movie Page send (S* / M*)

Single-sig send checks the typed address and amount against the spendable balance, shows the host's live fee tiers, reviews the payment and ends on a slip. A payment whose real fee is far above the estimate stops on Review for one more confirm. Without a key the wallet uses an offline demo balance (0.0125 BTC) and a mock payment. Multisig vault send collects mock signatures (Jade path is BLE demo without live sign_psbt).

## Sub-features

- `mp-s1-home` shows the single-sig balance and the last four transactions, every amount in compact BTC.
- `mp-s1-pull` reloads Home's balance and transactions when the page is pulled down.
- `mp-s2-backup-gate` blocks receive until backup confirmed.
- `mp-s3-receive` shows the wallet's address as a QR with copy and share, for a live wallet.
- `mp-s4-send` takes an address, an amount and a fee tier, checks the amount against the spendable balance, and says what is wrong with them.
- `mp-s4-keypad` closes the keyboard with the เสร็จ chip or a tap outside the address and amount fields.
- `mp-s4-fees` shows the host's live fee rates, or the board's fixed rates with a grey line when no host answers.
- `mp-s4-scan` opens the camera over Send to read a payment QR into the address field, and asks for the camera the first time.
- `mp-s5-review` shows what leaves and what stays, with the baht value when a price arrived, and signs. Send all shows its amount as an estimate.
- `mp-s5-high-fee` asks once more before posting a signed payment whose real fee is far above the estimate.
- `mp-s6-slip` shows the sent slip with the amount and fee that actually left, a txid, the send date, the baht value when a price arrived, and a share button.
- `mp-m1-m4` walks vault send → collect → (optional Jade demo) → broadcast mock.

## How to get to it (user POV)

- Home first-run → กระเป๋ากุญแจเดียว → ส่ง, or catalog SINGLE-SIG / SEND · VAULT.

## Gotchas

- Fee tiers come from the testnet4 host in use when Send opens, as sat/vB times a typical 141 vB payment. The app tries the build's own node first, when `vault-workspace/mobile-signer-ffi/esplora-host.local` named one at `ffi.sh build` time, then blockstream.info, then mempool.space. On testnet4 all three tiers have read 1 sat/vB (open item 72). The tier names and times are the board's. Before the first answer of an app run arrives, and whenever no host answers, the cards show the board's fixed 4, 8 and 15 sat/vB (564, 1,128 and 2,115 sat). Only the no-answer case adds the small grey line `id:fee_fallback` under them, which reads ใช้ค่าธรรมเนียมโดยประมาณ เพราะดึงค่าจริงไม่ได้. Review shows the fee as `≈ … sat`, an estimate. The slip shows the fee the signed transaction pays, which grows with the number of coins it spends. An emulator reaches the own node through the Mac's Tailscale route when Tailscale is up. `verify.sh adb shell svc wifi disable` and `svc data disable` before opening Send show the fallback. Rust remembers a live answer for five minutes and a fallback for thirty seconds.
- Receive leaves out the board's line about a fresh address every time (the address shown is the next unused one, so it changes only after money reached it, open item 60) and the logo tile the board draws over the QR (it would cover data modules). A wallet that is not live keeps the old screen, with no QR and no share, because money sent to its demo address is lost.
- **Receive, live wallet.** The QR, the address under it and the copy and share buttons side by side show only for a wallet whose snapshot loaded (`live`). That needs a key, such as the public test phrase through [import seed](./movie-page-import-seed.md), and a network that reaches a testnet4 host (see the fee tiers gotcha). On 2026-11-02 this Mac could not reach it, so the live screen was checked with a throwaway patch that sets `live = true` and a real testnet address in `SingleSigWallet.useDemoFixture()`, never committed. Open Home first (`id:cta_singlesig`), because Home binds the wallet and the catalog row `id:catalog_send/s3` alone shows an empty card. The row sits below the first screen of the route list: swipe it up three times, `idb ui swipe 201 700 201 300 --duration 0.4 --udid <udid>` on iOS. Then `verify.sh ios-see "id:ss_receive_qr"` and shot `mp-s3-receive`: the QR 196 dp square at the board's x 103, y 208, the address in two lines, copy and share at y 732. To prove the code reads, build the helper once, `swiftc -O .claude/skills/verify/scripts/qrdecode.swift -o /tmp/qrdecode`, then `/tmp/qrdecode <shot>.png` prints the address it found. `verify.sh ios-tap "id:cta_s3_copy"` puts the address on the pasteboard (`xcrun simctl pbpaste <udid>`), and `verify.sh ios-tap "id:cta_s3_share"` opens iOS's sheet with the address as text.
- Home leaves out the bottom tabs, the settings gear and the counterparty names on the transaction rows (a row says รับ or ส่งออก): the app has no tab navigation or settings screen yet, and the wallet knows no counterparty.
- **Home states.** A wallet that is the offline demo shows `0.0125 BTC` with a small demo marker. A wallet with a real key shows the balance with `≈ ฿…` under it and, when its history loaded, ธุรกรรมล่าสุด (`id:home_tx_label`) with up to four rows: รับ or ส่งออก, the date without น., a signed amount (+ green, the real minus U+2212 grey) and the confirmations (0 รอยืนยัน, 1 to 6 ยืนยัน N บล็อก, 7 and more ยืนยันแล้ว). Every BTC amount on S1 is compact, at least four places and every digit up to the eighth that is not zero, so 19,436 sat reads `0.00019436 BTC` and 1,250,000 sat reads `0.0125 BTC`. Each row starts with an arrow on a circle in the colours of board 3.6 Vault Detail. Money in is a navy arrow pointing down on a pale circle, and money out is an amber arrow pointing up on a warm circle. Board S1 Home draws the two colours the other way round, and the user chose 3.6 (open item 69). With more than four transactions, a ดูทั้งหมด link (`id:cta_s1_history`) sits right of ธุรกรรมล่าสุด and opens the full list, see [history](./movie-page-history.md). First-run Home is a different screen, and its hero `id:home_balance` shows the same compact amount without the unit, which is a separate text beside it, so 379,087 sat reads `0.00379087`. On the first bind of a key (relaunch the app, import the public test phrase, open Home through `id:catalog_send/s1`) the balance reads `—` with กำลังดึงยอด… and no demo marker until the chain answers; if it cannot be reached the dash stays with the retry line and a plain-words error (see Wallet unavailable). The rows need a reachable chain. On 2026-11-02 they were checked through a throwaway patch that gave the demo fixture a Live mode and five history rows (`.audit/phase2-c4b-home-probe.patch`, never committed): 25 of the 27 texts of board 4.1 were within 1.7 dp, and the fifth (unconfirmed) row stayed out because the list stops at four. The page scrolls as a whole when it overflows: expand the key details (`verify.sh ios-tap "id:key_details_toggle"`), then `idb ui swipe 200 750 200 250 --duration 0.4 --udid <udid>` moves everything up by the overflow, the navy block with it, and the status bar keeps a navy strip. The system text size (`xcrun simctl ui <udid> content_size …`) does not change the app's text.
- The scan chip shows only on a device with a camera, never on the iOS simulator. The scan sheet has no Penpot board (open item 59). The ฿ toggle, the gold baht line, the baht fee prices and `ใช้ได้ ฿…` need a price: without one the form is BTC and sats only, as before.
