# บทบาทและหน้าที่ของแต่ละฝ่าย

ระบบมีสามฝ่ายจริงที่ถือคีย์คนละ 1 ใน multisig 2-of-3 ไม่มีบุคคลที่สามลอยๆ ทำหน้าที่ arbitrator

## 1. ผู้กู้ (Borrower)

- เจ้าของ BTC ที่นำมาค้ำประกันเงินกู้
- ถือคีย์ในมือถือ (seed/private key อยู่ในแอป)
- Onboard ครั้งเดียว: import หรือ generate seed แล้วส่ง account xpub ให้ backend เก็บไว้ (ไม่ต้องส่ง private key)
- ทุกครั้งที่เปิด loan ใหม่ แอปฝั่งผู้กู้ derive child pubkey เองจาก xpub ที่ backend รู้จักอยู่แล้ว แล้วส่งมาพร้อม open-loan request เพื่อให้ backend ตรวจสอบ (verification flow)
- มีสิทธิ์ตรวจสอบ vault address ของตัวเองบนบล็อกเชนได้ตลอดเวลา
- เซ็นร่วมกับแพลตฟอร์มเมื่อ: คืนหลักประกันตอนใช้หนี้ครบ
- เซ็นร่วมกับผู้ให้กู้เมื่อ: fallback กรณีแพลตฟอร์มหายไปหรือถูกแฮ็ก

## 2. แพลตฟอร์ม (Platform)

- ผู้ดูแลระบบ ผู้พัฒนา/ผู้ให้บริการ
- ถือคีย์ใน HSM/KMS (ไม่ใช่มือถือหรือเซิร์ฟเวอร์ทั่วไป)
- รับผิดชอบ:
  - custody-service: track state ของ signing request ว่า PSBT รอเซ็นจากใครอยู่
  - policy enforcement layer: ตรวจสอบทุกคำขอเซ็นว่า output ตรงกับเหตุผลที่อนุญาตจริงก่อนเซ็น (ป้องกันการเซ็นผิดวัตถุประสงค์)
  - Monitor Service: ตรวจสอบ LTV ของทุก loan และ trigger margin call / liquidation ตามเกณฑ์
- เซ็นร่วมกับผู้กู้เมื่อ: คืนหลักประกันตอนใช้หนี้ครบ
- เซ็นร่วมกับผู้ให้กู้เมื่อ: liquidation ตอนผิดนัดหรือ LTV เกินเกณฑ์
- **ห้ามเซ็นได้ฝ่ายเดียว** — ต้องมีลายเซ็นที่สองเสมอ

## 3. ผู้ให้กู้ (Lender / ตัวแทนกองทุนรวม)

- ตัวแทนกองทุนรวม ถือคีย์เดียวแทนนักลงทุนทั้งหมด (ไม่ใช่นักลงทุนแต่ละคนถือคีย์เอง)
- **ยังไม่ล็อก**: ต้องกำหนดให้ชัดว่า custodian/ตัวแทนนี้ต้องอิสระจากแพลตฟอร์มแค่ไหน — ถ้าเป็นคนของแพลตฟอร์มเอง 2-of-3 จะเสียความหมายในทางปฏิบัติ (ดูรายละเอียดใน [`04-open-items.md`](04-open-items.md))
- เซ็นร่วมกับแพลตฟอร์มเมื่อ: liquidation ตอนผิดนัดหรือ LTV เกินเกณฑ์
- เซ็นร่วมกับผู้กู้เมื่อ: fallback กรณีแพลตฟอร์มหายไปหรือถูกแฮ็ก
- ใช้เครื่องมือ `lender-signer-cli` เซ็น PSBT แบบ offline
- **ความเสี่ยง operational latency**: ถ้าเซ็นช้าตอนราคาร่วงเร็ว หนี้อาจไม่ครอบคลุมพอ — มีข้อเสนอ (ยังไม่ตัดสินใจ) ให้ทำ policy-constrained auto co-signer ที่ HSM เซ็นอัตโนมัติเฉพาะ PSBT ที่ตรงเงื่อนไข whitelist

## ตารางสรุปการจับคู่เซ็นตามสถานการณ์

| คู่เซ็น | ใช้เมื่อ |
|---|---|
| ผู้กู้ + แพลตฟอร์ม | คืนหลักประกันตอนใช้หนี้ครบ |
| แพลตฟอร์ม + ผู้ให้กู้ | liquidation ตอนผิดนัด/LTV เกินเกณฑ์ |
| ผู้กู้ + ผู้ให้กู้ | fallback ถ้าแพลตฟอร์มหายไป/ถูกแฮ็ก |
